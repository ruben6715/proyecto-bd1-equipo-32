# Contribución individual -- Etapa 05
**Equipo:** 32  
**Integrante:** Romero Matias Luciano  
**Fecha:** 2026-11-2  

1. Aporte realizado

Diseño e implementación del script transaccional en T-SQL para la gestión automatizada de ventas
con control de inventario en lotes dentro del modelo mayorista FarmaBlue.
Estructuración lógica de bloques transaccionales utilizando BEGIN TRANSACTION, COMMIT TRANSACTION y
ROLLBACK TRANSACTION para garantizar la atomicidad y consistencia ante escenarios de éxito y fallo.
Resolución de conflictos de restricciones de unicidad (uq_numero_comprobante) y
validación de integridad referencial en tablas relacionadas (venta, detalle_venta y lote).

2. Decisiones en las que participé.
Aplicación estricta de las propiedades ACID para asegurar que una venta y
la actualización de su respectivo stock en el lote funcionen como una única unidad lógica de trabajo.
Incorporación de la selección dinámica del número de comprobante mediante funciones de agregación 
para evitar duplicidades al realizar pruebas sucesivas en el entorno de desarrollo.

3. Problemas o dificultades identificadas
Violación de la restricción de clave única (UNIQUE KEY constraint 'uq_numero_comprobante')
al intentar reejecutar inserciones manuales con números de comprobante estáticos ya existentes en la base de datos.
Desencadenamiento de errores de clave foránea (fk_detalle_venta_venta)
al fallar la cabecera de la venta y dejar el detalle sin un ID válido asociado.

4. Soluciones o propuestas realizadas
Modificación del script para calcular de manera automática el número de comprobante incremental
(SELECT @nro_comprobante = ISNULL(MAX(numero_comprobante), 1000) + 1 FROM venta), previniendo colisiones de datos.

Reestructuración de la lógica condicional en T-SQL para que el ROLLBACK TRANSACTION
intercepte de forma inmediata cualquier insuficiencia de stock antes de impactar las tablas relacionales.

6. Reflexión individual
Profundicé en el manejo avanzado de transacciones y control de concurrencia en SQL Server (T-SQL), 
comprendiendo la importancia crítica de los mecanismos de recuperación (COMMIT y ROLLBACK)
para mantener la integridad de los datos frente a operaciones críticas como el control de inventario farmacéutico
